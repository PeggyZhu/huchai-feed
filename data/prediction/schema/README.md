# 预测模块表结构

四份 JSON Schema 各描述一张正式表。校验器只实现这些文件里实际用到的关键字：`type`、`properties`、`required`、`additionalProperties`、`items`、`enum`、`const`、`minLength`、`minimum`、`maximum`、`exclusiveMinimum`、`$ref`、`$defs`，以及不参与判断的 `$schema`、`$id`、`title`、`description`。出现其它关键字时，校验直接失败。

正式 JSON 不是裸数组。外壳固定为：

```json
{
  "数据性质": "正式数据",
  "说明": "给人看的说明，校验器不把它当成数据行。",
  "columns": ["与 CSV 表头完全一致，顺序也一致"],
  "rows": []
}
```

`rows` 里的每一项都是一行。CSV 只有表头、没有数据行，编码是不带 BOM 的 UTF-8。某一格没有值时，CSV 留空，JSON 写 `null`，不要写空字符串。

`data/prediction/示例数据.json` 不是正式表。它的 `数据性质` 固定为「示例数据」，并且不能被周报读取。

## 出处列

业主确认的业务列保持原名。另外强制每一行都有来源和口径，缺一即拒绝。

| 表 | 来源列 | 口径列 |
| --- | --- | --- |
| 证据台账 | `来源URL` | `口径` |
| 项目 | `来源` | `口径` |
| 小区 | `来源` | `口径` |
| 观察池 | `来源` | `口径` |

来源必须是公开的 `http(s)` URL。口径必须是下表中的一个值，不能用斜线、顿号或「和」把两个口径拼在一起。

## 证据台账

`evidence.schema.json`。CSV 表头：

```text
小区,区,字段,值,来源URL,来源日期,口径,状态
```

- `状态`：`已确认` 或 `待核`。
- `口径`：`挂牌价`、`评估价`、`成交价`、`网签商业口径`、`房管局住房口径`、`结构属性`、`程序状态`。
- `值` 是字符串，按来源原文抄录。不把文字换算成数字。
- 字段名如果是 `挂牌价`、`评估价` 或 `成交价`，口径必须与字段相同。
- 字段名如果是 `户数`、`套均面积`、`建成年代` 或 `房屋类型`，口径必须是 `结构属性`。
- 字段名如果是 `程序状态`，口径必须是 `程序状态`。
- 拒绝作为字段名的派生结果：`超额涨幅`、`涨幅`、以「涨幅」结尾的名字、以及任何含「分数」的名字、`档位`、`总分`。这些要等后续里程碑从台账计算，不能写进台账。

`程序状态` 的原文可以包含这些阶段词：征询、冻结、决定、签约、腾退、两清、准动迁挂牌。校验器不把它们收成枚举，以免改写公告原文。项目表自身的类型只使用征询、冻结、决定、签约。

区名只使用：黄浦区、徐汇区、长宁区、静安区、普陀区、虹口区、杨浦区、闵行区、宝山区、嘉定区、浦东新区、金山区、松江区、青浦区、奉贤区、崇明区。

## 项目

`programmes.schema.json`。CSV 表头：

```text
项目名,文号,类型,日期,范围,来源,口径
```

`类型` 与 `口径` 使用同一组值，而且同一行两者必须相同：`征询`、`冻结`、`决定`、`签约`。

`来源` 必须已经出现在证据台账的 `来源URL` 中。先写台账，再写项目表。

## 小区

`communities.schema.json`。CSV 表头：

```text
名称,区,地址/弄号,户数,套均面积,建成年代,房屋类型,来源,口径
```

`口径` 只有 `结构属性`。`来源` 必须指向台账里同一小区名称的记录（台账列名是 `小区`，小区表列名是 `名称`，两边的文字要完全一致）。

`户数` 是整数或空白。`套均面积` 是平方米的数字或空白，列本身不设 70 的上限；`套均≤70㎡` 是观察池的硬过滤，写在决定里，不是这列的取值范围。`建成年代` 是四位年份或空白。`房屋类型` 是原文或空白，不预设类型表。

户数或套均面积不是空白时，台账里要有同一小区、同一 URL、同一口径、状态为已确认的一行，而且 `值` 是与该数字相等的纯十进制原文，例如 `80` 或 `62.5`。不能由校验器或周报把「约 80 户」收成 `80`。

## 观察池

`observation-pool.schema.json`。CSV 表头：

```text
小区,档位,分数分项,入池日期,最后证据日期,理由,来源,口径
```

`档位` 是 `高`、`中`、`低` 或空白。空白表示这一行只标注、不排档。

`分数分项` 在 JSON 里是对象或 `null`。对象的形状固定为 `{"程序": null, "量价": null, "结构": null}`，三个键都必须在，值是整数或 `null`。上限是程序 0–50、量价 0–30、结构 0–20。CSV 里这一格写同一段 JSON；整行不评分时这一格留空。

`口径` 是 `挂牌价`、`评估价`、`成交价`、`程序` 之一。口径为 `程序` 时，量价分必须是 `null`。

`来源` 可以有多条，用 ` | ` 分开。每一条都必须是台账里这个小区已经记录的 `来源URL`。`最后证据日期` 必须等于这些记录里最晚的 `来源日期`。档位或任一分数不是空白时，其中至少一条记录的状态是 `已确认`。

校验器只检查这些形状和出处。它不判断某一行该不该是「高」或「中」，也不计算分数。
