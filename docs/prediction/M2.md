# M2：官方公告抓取与小区匹配

M2 只做官方公告。它不抓 fangdi.cn，不绕过拦截，不改 `fangdi.json`，也不改周一的网签录入。

正式表 `data/prediction/` 仍然是空表。观察池要到 M5 才公开。样本写在 `samples/m2/`，`python3 -m huchai build` 不会把这个目录复制进站点。

2026-11-28 起，套数回测写在 `samples/m2/volume_backtest.md`。下面这份公告样本里的量价列仍是 `N/A (M3)`，因为样本只含程序证据，套数不写进 `sample.json`。公开预览页另由 `huchai.volume` 把程序证据和套数合在一起。

```bash
python3 -m huchai notices --since 2024-11-27 --until 2026-11-27 --out samples/m2
```

窗口默认是运行当天往前 24 个月。请求使用 `huchai-feed/1.0`，请求之间停顿。HTTP 403/412 不重试。抓不到的地址记入样本的「跳过」，不补一条公告。

## 来源

- 上海市人民政府主动公开公文库的公开检索接口 `https://www.shanghai.gov.cn/gwk/search/data`。这是公文库页面自己用来取列表和正文的接口。每条来源 URL 写成该接口返回的公文页 `https://www.shanghai.gov.cn/gwk/search/content/{id}`。
- 杨浦区「房屋征收与旧区改造」栏目的公开列表接口，以及列表里给出的公告页。公告页打不开就跳过，不用列表标题单独造一条。

关键词是房屋征收决定、房屋征收补偿方案、房屋征收范围、城中村。标题被认作项目公告之后才解析。补偿标准、管理办法、代表建议答复这类文件丢掉。

## 匹配

一条公告先抽出路名、弄号、门牌，再抽出小区、新村、花苑、花园、公寓这类名称。匹配只有四类：

| 结果 | 什么时候用 |
| --- | --- |
| 程序内 | 名称在标题或征收范围里，而且不是只出现在四至 |
| 部分覆盖 | 名称旁边写了「部分」 |
| 贴边 | 名称只出现在东至、南至、西至、北至 |
| 待核 | 只有路弄门牌，没有小区名 |

没有全市小区地址名录。所以不能从门牌数量推断「部分」。同一区、同一路弄在另一条已匹配公告里只对应一个小区时，才把待核地址回指到那个小区，置信度记 0.60。置信度是规则编号，不是模型打分：标题内 0.90，正文内 0.80，部分覆盖 0.70，贴边 0.85。

户数和套均只抄公告里的纯数字。带「约」，或同一条里有两个不同的户数，就保持空白。带「约」的原文不换算。

## 程序分和档位

上限仍是程序 0–50、量价 0–30、结构 0–20。量价这一列写 `N/A (M3)`。成交笔数还没有导入，少于 3 笔不打量价的规则无从适用。结构分没有点表，不另造，样本里结构为 null。

程序分取下面适用项的最大值，不累加。已冻结、已决定、已签约、已腾退的小区（匹配为程序内或部分覆盖）不打分，并退出候选。

| 匹配 | 公告 | 程序分 |
| --- | --- | --- |
| 程序内 | 征询 | 8 |
| 部分覆盖 | 征询 | 5 |
| 程序内 | 旧改公告或城中村 | 12 |
| 部分覆盖 | 旧改公告或城中村 | 8 |
| 程序内 | 征收范围 | 16 |
| 部分覆盖 | 征收范围 | 10 |
| 贴边 | 冻结 | 18 |
| 贴边 | 决定 | 28 |

贴边但公告类型只是征收范围时不记程序分：范围确认还不是冻结或决定。
| 程序内 | 两清或准动迁挂牌 | 40 |
| 部分覆盖 | 两清或准动迁挂牌 | 30 |
| 程序内的两清或准动迁挂牌，并且贴边已有征收决定 |  | 50 |

档位仍按 2026-11-25 的决定，程序分只用来排序：

- 高：两清或准动迁挂牌，并且贴边地块已有征收决定。还要过硬过滤。
- 中：贴边处于冻结或决定，本小区不在清单内，并且有超额涨幅。没有量价，不升为中。
- 低：只有超额涨幅。没有量价，不升为低。超额涨幅 ≥5% 为低、≥8% 为中，这两条留给 M3。
- 纯征询不升高。
- 硬过滤是户数>50 且套均≤70㎡。缺户数或缺套均，写成未知，不排档，也不补数字。
- 收储、成套改造、市政冻结、学区、对倒单独标成假阳性，程序分不作征收信号。

分档因此只来自程序。公开的户数和套均只决定硬过滤过不过，不另计结构分。
